== Conformance
This standard defines the OGC API - Joins core module. The core module specifies three operation sets: __discovery operations__, __data joining operations__ and __direct joining operations__. The server implementations are required to support the __discovery operations__ and they must support either one or both of the __data joining operations__ and/or __direct joining operations__.

The standardization targets of all conformance classes are "Web APIs."

The __discovery operations__ operation set is represented by the requirements classes "<<rc_core,Core>>".

The __data joining operations__ operation set is represented by the requirements classes: "<<rc_data_joining,Data Joining>>" and "<<rc_join_source_delete,Join Source Delete>>". The implementation of the "Data Joining" requirements class is mandatory, and the implementation of the "Join Source Delete" requirements class is optional for this operation set.

The __direct joining operations__ operation set is represented by the requirements class "<<rc_direct_joining,Direct Joining>>". 

The input data functionalities are represented by the requirement classes: "<<rc_file_uploading_with_query, Input File Upload>>", "<<rc_file_referencing_with_url, File Referencing with URL>>". The support for CSV input data format is mandatory for the __data joining operations__ and __direct joining operations__. The support for the GeoJSON input data format is mandatory for the __direct joining operations__.

The encoding formats are represented by requirements classes: "<<rc_json, JSON>>", "<<rc_html, HTML>>" and "<<rc_geojson, GeoJSON>>". 

The JSON encoding format support is mandatory, and the HTML encoding support is recommended for the service responses in the __discovery operations__ and __data joining operations__ operation sets. 

The GeoJSON encoding format is mandatory for the joined data output in the __data joining operations__ and __direct joining operations__.

The Core requirements class does not mandate any encoding or format for the formal definition of the API. One option is to use the OpenAPI 3.0 specification and "<<rc_openapi_3_0, OpenAPI 3.0>>" Requirements Class.
